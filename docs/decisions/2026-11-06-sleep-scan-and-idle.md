# /sleep の「何をやるか」の判定を、LLM ではなくスクリプトに移す

- 日付: 2026-11-06
- 決定:
  - `mise run sleep-scan`(`mise-tasks/sleep-scan`)が、レビュー・マージ確認・コンフリクト・レビュー対応・実装の対象を、REST と jq だけで洗い出す。対象がなければ `idle: true` を返し、`/sleep` は1行で終わる(手順書も役割ファイルも読まない)
  - 状態ファイルは持たない。「自分の最後の活動」と「他の人の最後の活動」を GitHub から比べて、対応済みかを決める。セッションが変わっても、同じ結果になる
  - 実機確認や承認を待つものは、`needs-human` ラベルで scan の対象から外す(`docs/kanban.md`)
  - 終了条件(マージ0件で終了、10ラウンドで終了)をやめる。ループは、ユーザーが止めるまで続ける
  - GitHub の操作は REST に統一する(`.claude/shared/github-rest.md`)。この環境では GraphQL が 403 になり、毎回書き直していたため
  - レビューの投稿前に、指摘が指すファイルがその PR の差分にあるかを確かめる(別の PR 向けの内容を取り違えた誤投稿を防ぐ)
  - 自分の PR のマージは、`status::ready-to-merge`(作成者以外が「指摘なし」)と CI 成功のときに、GitHub の auto-merge に任せる(`.github/workflows/automerge-ready.yml`)。`needs-human` があれば予約しない
- 理由: 対象がない回でも、手順書の読み込みと全件取得の判断に毎回トークンを使っていた。判定は機械的にできる。人に頼んでいたマージも、条件を決めて自動にできる。`updatedAt` は自分のラベル変更でも変わるため、更新の判定には使わない
