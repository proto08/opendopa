# レンタカー 2 データセットの集計・型・出す数字の決め方

- 日付: 2026-11-06
- Issue: #52
- 決定:
  - `rental_result`: 元の行で `FISCAL_YEAR == 2025` と `TOTAL_RENTAL_TIMES > 0` を絞ってから、`PREFECTURE_NAME` ごとに車両数・貸出回数・貸出日数・売上を合計し、緯度経度は平均する。1 台あたり売上は集計後の売上 ÷ 台数、平均貸出日数は集計後の日数 ÷ 回数。順位は、貸出のあった都道府県(2025 年度)の中での順位で、原稿には「集計した◯都道府県の中で」と書く(「全国」とは言わない)。
  - `rental_result` の売上・車両数に欠損の行(売上 5 行、台数 2 行)は、絞り込みで落とさずそのまま合計する(貸出回数の合計を、イシューのフィルタ条件どおりに保つため)。1 台あたり売上は、その分だけ厳密でない。
  - `rental_result` の `map` は、都道府県の点 1 つ。`points` の `size`(上位の強調)は YAML から指定できないので、強調は #59 で決める。`OPERATOR_ID` と `REPORTING_PERIOD` は集計に使わないので、シーンにも元の行にも出ない。
  - `rental_fleet`: 意味が確認できていない `TOTAL_SUM`・`NUMBER_OF_OFFICES_TOTAL` は使わず、営業所の行の `OWNED_VEHICLES_TOTAL`(0 と欠損は除く)を運輸支局ごとに合計した値だけを使う。原稿・大きな数字・見出しに出すのは順位と全体に占める割合だけで、車両数の絶対値は出さない(元の行 `csv_row` からも `hide` で外す)。ただし、検証用の `numbers` の記録には、順位を計算した元の値が入る。
  - `rental_fleet` は、運輸支局の列が空の行と、車両数が 0・欠損だけの運輸支局(実データでは 63 のうち 59 が残る)を動画にしない。
  - 2 つとも、型(テンプレート群)は順位だけで決まるので、決定モデルを使わずに規則(`fallback_rules.by_rank`、`rules` プロバイダー)で選ぶ。型は 4 つずつ(言い回しの違い)。
  - 原稿に固定の数字(「上位3位」「1台あたり」など)を書かない(品質ゲートの数字の照合が、元の行にない数字を弾くため)。
  - 小数の表記用に `fmt: decimal`(小数 1 桁まで。単位なし)を足し、`rank_in_group` の `<name>_n` を穴・式で使える名前(`defined_names`)に含めた。
  - 実データでの件数: `rental_result` 25 本(都道府県が 25)、`rental_fleet` 59 本。
- 理由: イシュー #52 と docs/data.md §10.5・§10.6 の指示どおり。意味が曖昧な列は、確認できるまで順位と割合だけに限り、絶対値は出さない。
