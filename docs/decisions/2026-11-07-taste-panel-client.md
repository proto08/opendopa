# 好みパネルは、サーバーの taste を描くだけにし、「見た動画」はクライアントで補う

- 日付: 2026-11-07
- Issue: #49
- 決定: (1) 地図で「見た動画」を濃くする判定は、この画面で視聴を送った動画と、`taste.log`(最大6件)に出ている動画の和集合にする。リロード後は、直近6件より前の動画は薄く戻る。(2) 視聴は動画ごとに新しい `viewId` で、60% を下回る・タブが隠れる(`visibilitychange`)・`pagehide` のときに1回だけ送る。タブが戻ったときは、表示中の動画を新しい `viewId` で数え直す。ページを離れる最中は `sendBeacon`、それ以外と beacon が断られたときは `keepalive` の `fetch`。(3) 0 秒の視聴も送る(60% まで見えてすぐ離れた動画は「見ていない」の信号になる)。(4) 軌跡は、この画面で受け取った `taste` の `x`,`y` を最大24点まで持つ(リロードで消える)。(5) 好みの現在地の移動は、`<g>` の CSS `transform` の transition(0.7秒 ease-in-out)。`prefers-reduced-motion` では transition を切る。
- 理由: (1)(4) `/api/feed` は見た動画の全一覧と過去の位置を返さず、設計書 §6.4 の形を変えずに済ませるため。ブラウザで好みの計算はしない。(2) §6.2 の `sendBeacon` 想定と「同じ視聴で2回送らない」を満たすため。(5) SVG の属性アニメより CSS の transition のほうが、中断・再開が自然で、reduced-motion の切り替えも CSS だけで済む。
