# pipeline のタグ: 地域の元の列を YAML の `region_from` に書き、都道府県を複数取れるデータは全部付ける

- 日付: 2026-11-07
- Issue: #151
- 決定: データ種別のタグは `tag:`(表示名。ID の slug は `tags.py` の `DATASET_TAG_SLUGS`)、地域の元の列は `region_from:`(列名のリスト)に書く。`naiko_route`(積み港・降ろし港)と `flightplan`(出発・目的地)は両方の都道府県を地域タグにし、同じ県は 1 つにする。`naiko_ship` と `rail_*` は地域タグを付けない(`naiko_ship` の `Address` は事業者の所在地で、事業者を特定しないため使わない)。省略形(「東京」)は、全文が一致するときだけ都道府県にする。`rental_fleet` は集計後も地域を残すため、`aggregate` に `first` を足した。`derive.PREFECTURES` は `tags.py` に移した。
- 理由: 設計書 §3.3 の「元データにない地名を作らない」を守りつつ、取れる地名は漏らさないため。列を YAML に置くと、データセットを足すときにコードを触らずに済む。先頭一致だけだと「東京」を拾えないが、前方一致で省略形を許すと「東京ドーム周辺」を誤って都道府県にするので、全文一致に限った。
