# 判断モデルは本体の環境に CPU・外部 ingress で置く(GPU・専用 VNet・内部 LB をやめる)

- 日付: 2026-11-06
- Issue: #58
- 決定: (1) 判断モデルの Container App(`infra/modules/decider`)は、本体の Container Apps Environment(`modules/containerapp` の `environment_id`)に追加する。GPU の workload profile、専用 VNet、専用 Environment、内部ロードバランサー、private DNS は作らない。(2) リージョンは本体と同じ japaneast。`decider_location` 変数は削除する。(3) CPU で動かす。consumption の上限内で cpu 4・memory 8Gi を既定とし、`decider_cpu`・`decider_memory`・`decider_min_replicas` で変えられる。`min_replicas` の既定は 1(モデル読み込みが重いため)。`gpu_profile_type` は削除する。(4) `decider_enabled = false` が既定のまま。`true` にするのは、費用を理解した人が明示的に行うときだけ。(5) ingress は外部(`external_enabled = true`、`target_port = 8000`)。認証は `Authorization: Bearer <STRANDS_DECIDER_TOKEN>`。`decider_token` は 16 文字以上(既存のバリデーションを維持)。(6) レジストリの AcrPull は、既存パターンどおりユーザー割り当て ID + ロール割り当て。(7) `STRANDS_DECIDER_URL` は外部 URL(`terraform output decider_url`)。`Makefile` の `deploy-decider`、`.env.example`、設計書 D14・§12.1 の配備先、`docs/data.md` をこれに合わせた。(8) トークンが漏れたとき、第三者が判断 API を呼べる(CPU を使われ、費用と負荷が増える)。判断モデルは CSV の列から選択肢を選ぶだけで、DB・Blob・秘密には触れない。漏れた疑いがあれば、人が `decider_enabled = false` にして `terraform apply` し(Container App ごと消える)、トークンを作り直してから有効化し直す。(9) `strands_azure` が失敗して `rules` にフォールバックしたときは、件数をログ(標準エラー)に出す(黙ってフォールバックしない)。
- 理由: Azure は動けばよく、リージョンは日本と決まった。Japan East にはサーバーレス GPU がなく、GPU を使うには別リージョンか専用 VNet と専用 Environment が要る。それだと実行場所の分散、VNet・DNS の整備、パイプラインから届かない問題が増える。2B モデルは CPU で遅くても、判断は件数が少なく(事故50行)実行時に呼ばないバッチなので許容する。外部 ingress にするのは、パイプラインを手元 PC や CI で動かせるようにするため。公開の代わりにトークンと「既定では作らない」運用で守る。
- 関連: 設計書 D14 の「配備先(GPU付きContainer Apps か Azure ML)」と §12.1 の「内部のみ」は、この決定で読み替える(設計書も更新済み)。2026-11-06-strands-azure-provider.md の (3)(6) を置き換える。未確認: terraform が手元になく `validate` / `plan` は未実施。CPU 推論の速度とモデルの入手元・ライセンスも未確認。
