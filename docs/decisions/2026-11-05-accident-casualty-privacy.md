# accident の負傷の内容は、原稿・判断・元の行のどこにも出さない

- 日付: 2026-11-05
- Issue: #34
- 決定:
  - `CASUALTIES_SUMMARY` は、`derived.casualty_sentence`(「人的被害は、報告にありません。」か「負傷者の報告があります。」)にだけ変換して使う。
  - 判断モデル(`template`)の `state` には `CASUALTIES_SUMMARY` でなく `casualty_sentence` を渡す。
  - `hide: [CASUALTIES_SUMMARY]` で、`videos.csv_row` にも出さない。
  - 型 `injury` のテンプレートは、概要の引用(`summary_1`・`summary_2`)と機体の被害の行を使わない(負傷の部位や症状が書かれうるため)。 ← 2026-11-06 に `summary_1` も外した(#108)。
  - 負傷者ありの動画は `comments: []`(`comments.rule` で `none`)。
- 理由: 設計書 §15.2「負傷の部位や症状は読まない」。docs/data.md の YAML 例は `state` に `CASUALTIES_SUMMARY` を挙げていたが、モデルに負傷の内容を渡さずに済むので、定型文にしたものを渡す。

## 追記(2026-11-06、#108)

- 実データで確認したところ、型 `injury` が `summary_1`(概要の1文目)を字幕に使っていて、負傷の部位(指・腕・顔・膝など)が出ていた。この決定が守っていたのは `CASUALTIES_SUMMARY` 列だけだった。
- 修正:
  - `injury` の標準テンプレートから `{summary_1}` を外した(短い版は元から使っていない)。
  - 品質ゲートに `casualty_detail` を足した(`gate.check_casualty_detail`)。負傷を示す語(負傷・打撲・骨折など)と同じ文に部位の語がある、または部位の語のすぐ後ろに「接触」があるとき、その動画を除外する。概要・再発防止策の引用は、型を問わずこの検査にかかる。
  - 部位の語は、機体の部品(腕部固定金具、機首部、脚の破損)や別の語(運転手、不足、目的、指示)にも使われる。そのため、負傷を示す語と同じ文にあるときだけ部位とみなす。
- 実データ(194行)の結果: 189本 → 188本。除外は `casualty_detail` 1行(No.100。再発防止策の引用に「指先を負傷した」)が増え、その他は変わらない(forbidden 2、too_long 2、filter 1)。型の内訳は `injury` 27(以前は 28)。字幕・見出し・チップに、人の負傷の部位は出ていない(部位の語が残るのは、機体の部品、「足元」、「指示」など)。
- 限界: 語の一覧による検査なので、一覧にない言い方(「手背」の「背」など)は検出できない。新しいデータセットを足すときは、部位の語を見直す。
- レビュー対応(#109): 検査の対象を字幕(`lines`)だけでなく、見出し(`headline`)・チップ(`chips`)・コメント(`comments[].text`)にも広げた(`check_all` の `extra_texts`)。現状の accident では負傷者ありの動画は `comments: []` で、見出しも引用を含まないが、将来の型やデータセットで引用が入っても素通りしないようにする。
