# recsys の candidateIds は純粋関数の引数で絞り、候補が数本のときも選び方は変えない

- 日付: 2026-11-07
- Issue: #153
- 決定: `pick_next` に `candidate_ids: Option<&[String]>` を足す。`None` は今と同じ。`Some` なら、索引にある動画のうち ID が含まれるものだけを候補にする(索引にない ID は無視)。
  - 候補が 0 本なら、`picks: []`、`seenReset: false`、レスポンス直下に `reason: "pool_empty"` を返す(`taste` は返す。`reason` は空でない結果には付けない)。
  - 絞った候補が全部配信済みなら、今と同じく `seenReset: true` で、候補全体から選び直す(`pool_empty` にはしない。呼び出しの途中で尽きたときは、`count` より少なく返す)。web(#145 の子イシュー)は、絞り込み中の `seenReset` で `impressions` を全部消すと絞り込み外の配信済みも消えるので、扱いを決めること。
  - 選び方(近傍・探索・冒険・連続制限)と好みの更新式は変えない。
- 理由: `hashtag_design.md` §5.2 の「選び方は変えない」に従い、候補の集合だけを変えた。候補が尽きたとき(全部配信済み)の扱いは §5.2 の 4 が曖昧なので、「候補が空 = `pool_empty`」(イシューの文言どおり)と「一巡 = `seenReset`」(既存の約束、ADR-0040 A1)を分けた。
- 確認(疑似ユーザー。`recsys-core/tests/simulation.rs` の `few_candidates_discovery_streak_and_reset`): 候補 5 本(rail 3、akiya 2)、rail を最後まで見るユーザー、10 seed x 15 本。
  - 候補の外は一度も出ない。一巡(5 本)の間は重複せず、全部見たときだけリセットされる(15 本で 2 回)。
  - 発見: 最初の 2 本で、必ず 2 つのデータセットが両方出る(`first` のあと `explore_cold` が未出のデータセットを選ぶ)。3 本目以降は、好みに寄る `near` が中心で、`adventure` も出る。
  - 連続: 候補が 2 データセットだけなので、同じデータセットが 3 本続くこと自体は起きうる(連続制限は、他に候補があるときだけ効く。既存の挙動)。一巡の境目では、同じ動画が続けて出ることがある(リセット後の最初の 1 本が、直前の動画と同じ)。数本の絞り込みでは許容する。
- 関連: ADR-0040 A1
