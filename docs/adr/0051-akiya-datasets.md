# ADR-0051 データセット: 空き家バンク(akiya_reg・akiya_sold)

- Issue: #51
- 日付: 2026-11-06
- 状態: 決定

## A1 実測の結果(`rules` プロバイダー、キャッシュなし)

- 決定: `datasets/akiya_reg.yaml` と `datasets/akiya_sold.yaml` を置いた。`uv run opendopa generate` の結果は次のとおり(数字の不一致は両方 0、所要は 1 データセットあたり約 3 秒)。

| データセット | 生成 | 除外 | 推定秒数(最小/中央/最大) | 型の内訳 |
| --- | --- | --- | --- | --- |
| `akiya_reg` | 149 本 | 2,846 行(`AMOUNT/RENT` が欠損・0: 2,845、重複: 1) | 15.0 / 15.0 / 18.3 | access 70、other 36、nature 22、space 15、shop 6 |
| `akiya_sold` | 148 本 | 15,161 行(成約価格が欠損: 14,007、売り出し価格が欠損: 933、値下げ率が ±50% 超: 219、重複: 2) | 15.0 / 17.7 / 24.8 | access 80、nature 26、other 26、space 11、shop 5 |

- 理由: 受け入れ条件(目安 100 本以上、数字の不一致 0)の確認と記録。10 億円以上の行は `akiya_reg` に 0 行だった(最大 9.03 億円)。`akiya_sold` は成約価格の記入が約 12% しかなく、これが除外のほとんどを占める。

## A2 成約価格が欠損の成約物件は動画にしない

- 決定: `akiya_sold` は `CONTRACT_INFO_AMOUNT/RENT` が欠損の行を、クリーニング(`filters`)で除外する。
- 理由: 大きな数字を「成約価格」にするため。欠損でも売り出し価格で動画にすることはできるが、「成約しました」の動画に価格がない・別の価格が出ると誤解を招く。残る約 2,100 行から `cap=150` を選べる。

## A3 `derived` に op を足した(エンジンの流れは変えない)

- 決定: `format`(`prefix_if` で賃貸に「月」を付ける)、`pct_diff`(値下げ率。`only_positive`)、`ensure_suffix`、`year_of`、`years_since`、`flag_present`、`free_sentence` を足した。別の列を見る op のため、`derive_op(name, frame=True)` で DataFrame 全体を受け取れるようにした。築年数の基準の年は、実行のたびに値が変わらないよう YAML に `as_of_year: 2026` と書く。
- 理由: 「賃貸は月額で別の言い回し」「値下げ率は両方が正のときだけ」は、複数の列にまたがるため。

## A4 自由記述 `STRONG_POINTS` は、使える最初の1文だけを「紹介文には、「…」とあります。」の形で出す

- 決定: `free_sentence` は、①記述のどこかに電話・メール・番地らしい文字列があればその記述ごと使わない ②最初の行の最初の1文だけ(2文目に進まない) ③40 字以内 ④屋号・広告・問い合わせの語(株式会社、不動産、お問い合わせ、詳細 など)、括弧・`※`、`！` の連続、**数字**(全角を含む)を含む文は使わない ⑤`♪♡★` などの記号は取り除く。出すときは「紹介文には、…とあります」と出典を示す形にする。
- 理由: Issue と data.md §10.3 の規則に加え、自由記述の数字(「1,400㎡以上」「売価430万円」など)は単位・時点を確かめられず、面積・価格の列とずれうるため(面積と敷地の数字は読まない約束)。出典を示す形にして、記述を事実として言い切らない。

## A5 広告らしさの判定(`stronger_ad`)は、行を除外せず、その文だけ使わない

- 決定: 判断(noul)に `drop: <列>` と `drop_if_probability_above` を足した。確率が超えたら、その行の列の値だけを欠損にする(行は除外しない。判断の記録に `dropped: true`)。`rules` プロバイダーは `regex_pii` だけで判定するので、広告のキーワードは `free_sentence`(derived)で先に落としておく。
- 理由: Issue は「確率が 0.5 を超えたらその文を使わない」。既存の `exclude_if_probability_above` は行ごと除外するため。文は任意の行なので、型の選択肢(埋められる型)は変わらない。

## A6 型は、行の事実で埋められるものだけが選択肢になる

- 決定: 型(nature / access / space / shop / other)のテンプレートは、その型の必須の穴(紹介文、最寄り駅、庭、事業用・店舗の区画)を持ち、行にその事実があるときだけ、その型が決定モデルの選択肢になる。文面は、どの型でも事実を述べるだけ(「自然豊かな」などと言い切らない)。型は、どの事実を取り上げるかを決める。
- 理由: 決定モデルが選び間違えても、事実と違う原稿にならないため。

## A7 読み上げない数字

- 決定: 面積(`OCCUPATION_AREA`)・敷地(`SIZE_OF_LOT`)・最寄り駅までの距離(`akiya_reg` は分とメートルが混在、`akiya_sold` は「250m」「20分」の文字列)は、原稿に出さない。`LAYOUT` の `R`(間取りとして読めない。10,068 行)と「指定なし」は欠損にする。
- 理由: 単位が確認できないため(data.md §10.3)。

## A8 元の行(`csv_row`)に出さない列

- 決定: `STRONG_POINTS`、`TOILET_NOTE`、`BATH_NOTE`、ID(`PROPERTY_NUMBER_ID`、`ID`)を `hide` にする。列名の `AMOUNT/RENT` は式に書けないため `AMOUNT_RENT`(成約は `CONTRACT_AMOUNT`)に置き換えるので、元の行の列名もこれになる。
- 理由: 自由記述には電話番号や屋号が混ざり、画面の「元データ」にそのまま出すと個人情報・広告の混入を防げないため(設計書 §15.2)。

## A9 選定

- 決定: `cap=150`、`PREFECTURE` で順番にばらす。点数は `STRONG_POINTS` に記入があれば +1(Issue のとおり、記入の有無で、使える文かどうかではない)。同点は元の行の順。
- 理由: Issue のとおり。
