# ADR-0041 recsys: 内部 HTTP API とインデックスの読み込み

- Issue: #41
- 日付: 2026-11-06
- 状態: 決定

## A1 索引の入れ替え

- 決定: 索引(`Snapshot` = `Index` + `u0`)を `RwLock<Option<Arc<Snapshot>>>` に持つ。`reload` は、ロックの外で新しい索引を作り終えてから、`Arc` を差し替える(書き込みロックは差し替えの一瞬だけ)。リクエストは `Arc` を複製して使うので、入れ替え中も止まらず、処理中のリクエストは古い索引で最後まで答える。`ArcSwap` は依存を増やすだけなので使わない。
- 理由: 読み込み(DB 往復)とロックを切り離せば足りる。リクエストの頻度に対し、`RwLock` の競合は無視できる。

## A2 起動時の読み込みに失敗したとき

- 決定: 起動は止めず、HTTP を先に立ち上げる。バックグラウンドで 1 秒から始めて倍々(最大 30 秒)の間隔で、成功するまで再試行する。成功するまで `/healthz` と `/internal/feed|taste` は 503(`{"error": ...}`)。`/healthz` が 503 の間は Container Apps の probe がトラフィックを流さない。`reload` の失敗は 502 を返し、古い索引を残す。索引が空(`status='ok'` の動画が 0 件)のときは、`/healthz` は 200(件数 0)、`feed`/`taste` は 503。
- 理由: DB の起動待ちやパイプラインの公開前でも、コンテナが落ちて再起動を繰り返すより、待つほうが運用しやすい。

## A3 DB の読み方

- 決定: `sqlx`(postgres、`tls-rustls`)の実行時クエリ(マクロは使わない。ビルドに DB が要らなくなる)。3 つの SELECT は `REPEATABLE READ READ ONLY` の 1 トランザクションで読み、内容がずれないようにする。pgvector の型は crate を足さず、`embedding::text` を `[a,b,...]` として解析する。`meta` の `key='centroid'` は JSON の数の配列とし、長さ 1 に正規化して `u0` にする。`meta` に無いとき(パイプラインがまだ書いていないとき)は、動画の埋め込みの平均を正規化して使う。次元が動画・クラスタ・`u0` でそろわなければ読み込みの失敗として扱う。
- 理由: 依存を増やさず、読み込みは起動時と `reload` だけなので速度は問題にならない。

## A4 リクエストの検証と乱数

- 決定: 本文は `Bytes` で受けて自分で解析し、不正な JSON・欠けた項目・不正な `type`・範囲外の `count` はすべて 400(axum の既定の 422 にしない)。`seenIds` / `recentDatasets` は省略可(空)。乱数は、起動時刻から作った種に定数を足しながらリクエストごとに別の `Rng` を作る(ADR-0040 A6)。係数は環境変数 `RECSYS_CONFIG`(TOML のパス)があればそのファイル、なければ既定値。
- 理由: エラーの形を `{ "error": ... }` と 400 にそろえるため。

## A5 DB 統合テスト

- 決定: `mise run recsys-db-test` が使い捨ての DB に migrate・シードし、環境変数 `RECSYS_TEST_DATABASE_URL`(読み取り専用ロール)つきで `cargo test --test db` を流す。この環境変数がなければテストは何もしないので、`mise run test`(DB なし)は通る。
- 理由: `db-test` と同じく、docker の DB が要るテストは別タスクにする。
