# sleep: マージ確認担当(PRごと)

自分がレビュー済みの他の人のPRについて、その後の更新で指摘が直ったかを確認し、マージ可能なら確認なしでマージする。

入力: PR番号。原則は呼び出し元のプロンプトで渡される。

## 手順

1. PR のラベルを `status::merge-check` にする(既存の `status::*` は同じコマンドで外す)。
2. 自分の指摘を一覧にする。
   - `gh pr view <番号> --json reviews,comments,commits,mergeable,reviewDecision,statusCheckRollup,isDraft`
   - `gh api repos/{owner}/{repo}/pulls/<番号>/comments`(行コメント)
   - 出力が大きいときは `--jq` で、自分のレビュー本文・行コメントと、それ以降の commit・作成者の返信だけに絞る。
3. 自分の最後のレビュー以降の commit と作成者の返信を読み、`gh pr diff <番号>`(必要なら自分の最後のレビュー時点との差分)で、各指摘が**実際にコードで直っているか**を確認する(返信の文面だけで判断しない)。対応しないという返信は、理由が妥当かを判断する。
4. テスト・lint は、`.claude/shared/review-criteria.md` の「テスト・lint を実行するかの判断」に従う。指摘箇所の修正に関係する範囲だけを、必要なときに実行する。worktree は `../opendopa-pr-<番号>`(既存があり未コミットの変更がなければ再利用、あれば別名)。
5. 次をすべて満たすとき「マージ可能」とする。
   - 自分の指摘がすべて対応済み、または対応しない理由が妥当。
   - `.claude/shared/merge-rules.md` の確認を満たす。他のレビュアーの変更要求も残っていない。
6. **マージ可能なら、確認なしでマージする**(`.claude/shared/merge-rules.md`)。
7. **マージ可能でなければ、マージしない。**
   - 未対応の指摘があれば、`gh pr comment` で作成者に `@<ログイン名>` で伝える(「対応済みの確認結果」と「残っている指摘」を簡潔に)。
   - 競合・CI失敗・CI待ちは、事実のみ短くコメントする。
   - いずれも承認・変更要求はしない。
   - `status::merge-check` を `status::changes-requested` に付け替える。
8. 判断に迷う場合(対応が部分的、対応しない理由の妥当性が微妙、など)は**マージしない**。理由を報告に書く。
9. 後片付け: 変更がない worktree とローカルブランチは削除する。起動した docker 等も削除する。

## 返す報告(短く)

PR番号、各指摘の対応状況、マージしたか(しなかった理由)、クローズされたイシュー
