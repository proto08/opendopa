# 決定事項の記録(ADR / DECISIONS.md)

実装・レビュー対応の中で決めたことは、規模に応じて次の2か所に残す。記録は実装と同じcommit(または同じPR)に含める。

| 種類 | 書き先 | 目安 |
| --- | --- | --- |
| イシュー単位の大きな決定 | `docs/adr/NNNN-<description>.md`(NNNN はイシュー番号を4桁ゼロ埋め) | ツール・構成・境界など、後から覆すと影響が大きく、理由まで残したいもの |
| 実装中に決めた小さな決定 | `docs/DECISIONS.md` の「小さな決定」に1行 | ライブラリの選択、命名、挙動の細かい判断など |

- **`docs/DECISIONS.md` がなければ**、次の構成で作成する。
  - 見出し「決定の記録」と、ADR・小さな決定の使い分けの説明
  - 「ADR の一覧」表(列: ADR / 題 / Issue)
  - 「小さな決定」節
- **小さな決定**: `- YYYY-MM-DD: 決定。理由: ...(関連するADRがあれば ADR-NNNN AX)` の形で、「小さな決定」節に追記する。日付は `date +%F` で取得する。
- **ADR**: `docs/adr/NNNN-<description>.md` を作成する(既存ファイルがあれば追記・更新する)。形式は次のとおり。決定ごとに `A1`, `A2`, ... と連番を振る。
  ```markdown
  # ADR-NNNN <題>

  - Issue: #<番号>
  - 日付: YYYY-MM-DD
  - 状態: 決定

  ## A1 <決定の題>

  - 決定: ...
  - 理由: ...
  ```
  - 作成・更新したら、`docs/DECISIONS.md` の「ADR の一覧」表に行を追加する(既にあれば題を更新)。
- 設計書(`docs/design_doc.md` など)の内容と食い違う決定をした場合は、設計書も合わせて更新する。イシュー本文は更新せず、読み替えが必要なら PR 説明欄に書く。
- 決定がなければ、何も作らない(空のADRや「なし」の記録は不要)。
- 他の決定と矛盾しないよう、書く前に既存の `docs/adr/` と `docs/DECISIONS.md` を読む。
